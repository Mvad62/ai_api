# Telegram-бот с контекстом

Минимальный бот на aiogram 3 с историей переписки в памяти процесса. Используется
совместимый с OpenAI Chat Completions API: стандартный адрес — OpenAI, адрес и
название модели можно задать для прокси через `.env`.

## Запуск

1. Создать виртуальное окружение и установить зависимости:

   ```powershell
   py -m venv .venv
   .\.venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   ```
2. Скопировать `.env.example` в `.env`, указать `BOT_TOKEN`, `ANYMODEL_KEY` и
   `ANYMODEL_MODEL` (обязательны). Для прокси задать `ANYMODEL_BASE_URL`
   (корневой URL API, без `/chat/completions`).
3. Запустить `python bot.py`.

Если Telegram вернёт `Flood control exceeded` при проверке `GetMe`, бот подождёт
указанное сервером время, увеличивая паузу с каждой попыткой (всего до четырёх
попыток), и затем остановится с понятным сообщением в журнале. Каждый запрос во
время блокировки продлевает её, поэтому не запускайте несколько копий бота с
одним токеном. Если ограничение не снимается, отзовите токен в BotFather
(`/revoke`), укажите новый в `.env` и запустите бота заново. При недействительном
или отозванном токене бот сразу останавливается с сообщением об ошибке.

`/reset` очищает контекст пользователя. История не переживает перезапуск бота;
сохраняются последние `MAX_HISTORY_MESSAGES` сообщений на пользователя.

## Параметры и логирование

Модель задаётся через `ANYMODEL_MODEL` и обязательна. По умолчанию
`temperature=0.7`, `max_tokens=1000` и 20 сообщений истории. Параметры запроса (модель,
temperature, max_tokens, число сообщений и их роли) и ошибки пишутся в журнал.
Содержимое переписки и API-ключ намеренно не логируются.
При успешном ответе также журналируются usage из ответа API и `x-request-id`,
если сервис его возвращает.

## Короткий отчёт о прогонах

Прогоны не выполнялись: в рабочем окружении нет учётных данных API, поэтому
токены, стоимость и ID запросов нельзя подтвердить. Заполнить строки по данным
Usage в OpenAI или кабинета используемого прокси. Стоимость ориентировочная и
зависит от тарифа на дату прогона; фиксировать входные и выходные токены раздельно.

| Модель | Temperature | max_tokens | № прогона | Эффект (сжатость/креатив) | Токены (вход/выход) | Ориентировочная стоимость | ID запроса |
|---|---:|---:|---:|---|---:|---:|---|
| — | — | — | — | Нет данных: прогоны не запускались | — | — | — |

После тестирования приложить сюда скриншот Usage (для OpenAI) либо ID запросов
из кабинета прокси-сервиса. Не добавлять в репозиторий `.env` или секретные ключи.
